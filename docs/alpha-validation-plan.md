# Alpha 驗證開發計畫

## 目標

把目前可玩的規則原型推進到可穩定試玩與批量驗證的 Alpha Validation Build。

此階段不擴張卡牌池、不加入後端、不處理正式美術，也不修改 UI 介面與美術呈現。

## 已鎖定規則基準

- 勝利門檻：11 裁決點數。
- 起始裁決點數：6。
- 出局門檻：0。
- 回合上限：10。
- 宿命正式作為獨立宣告階段，位於發言階段後、出牌階段前。
- 宿命不列入公開型功能牌觸發順序；目前公開型功能牌觸發順序只包含真理之眼。
- 宿命仍占用每回合最多 1 張功能牌的使用額度。

## 本階段不碰範圍

- 不修改 `src/components/` 的 UI 流程與視覺呈現。
- 不修改 `src/styles/`。
- 不新增、替換或壓縮美術與音訊素材。
- 不實作混沌、鏡像、賭命、權宜牌。
- 不新增後端、資料庫、登入或線上多人。

## Sprint 1：非 UI 平衡驗證（已完成前置條件）

目標：用既有 simulator 核心產出可判讀的平衡結論。

狀態：先前已完成 1000 局模擬，本階段不重新執行。若後續規則數值、Bot 決策或卡牌效果改動，再重新跑 baseline 與 Balance Profile。

工作項目：

1. 以 baseline 11 點勝利門檻跑 100 / 500 / 1000 局。
2. 比較 `legacyTarget12`、`maxRounds8`、`higherVolatility`、`harsherBrokenPromise`、`legacyTarget12_harsherBrokenPromise`。
3. 記錄平均回合數、勝利原因比例、人格勝率、守諾率、局勢頻率、功能牌使用次數。
4. 若某人格明確勝者勝率超過 55%，列為平衡風險。
5. 若回合上限結束比例超過 45%，列為節奏風險。

驗收標準：

- `npm run test` 通過。
- `npm run build` 通過。
- 已完成至少一次 1000 局模擬觀察。
- 若規則再改動，能用 simulator 既有函式重現同一組 profile 的比較結果。

## Sprint 2：人工試玩驗證（已完成）

目標：驗證玩家是否理解承諾、失信、宿命、真理之眼與結算。

狀態：真人測試已完成，流程上沒有明顯問題。若後續規則、Bot 決策或 UI 流程改動，再重新執行回歸試玩。

建議流程：

1. 找 3 到 5 名測試者。
2. 每人至少玩 1 局，理想為 2 局。
3. 每局記錄完成時間、結束回合、勝者、玩家是否理解加扣分。
4. 詢問玩家是否有至少一次明顯猶豫：守諾或失信、合作或背叛、用牌或保留。
5. 記錄玩家最不理解的一個規則點。

通過標準：

- 玩家能在 3 到 5 分鐘內理解基本流程。
- 玩家能說出自己上一回合為什麼加分或扣分。
- 玩家能理解宿命是在出牌前宣告，不是在出牌階段暗放。
- 至少多數玩家願意再玩一局。

結果：

- Flow Gate：Pass。
- 目前沒有流程阻塞問題。
- 詳細數據與逐局訪談未記錄於本文件；若進入數值調整或正式測試，再另建 playtest report。

## Sprint 3：Bot 壓力與發言設計（已接入發言階段 UI）

目標：在不改 UI 的前提下，先定義 Bot 發言資料與驗證方式。

狀態：已新增 Bot 發言資料與測試，並已接入發言階段 UI。對手座位卡會顯示人格標籤，發言階段會顯示對手發言。

工作項目：

1. 定義守信型、投機型、觀望型的短句語氣。（已完成）
2. 發言內容不得洩漏 hidden faction。（已用測試覆蓋）
3. 發言只作為心理壓力，不作為保證資訊。（已完成）
4. 先寫資料與測試，再接入 UI。（已完成）

驗收標準：

- 發言資料能依人格分類。
- 測試可確認每種人格至少有一組可用語句。
- 發言 UI 不應遮擋主要出牌與階段推進操作。

## Alpha Gate

進入下一階段前需滿足：

- 核心規則、文件、測試一致。
- 11 點勝利門檻不再與文件衝突。
- 宿命獨立宣告階段已被文件與測試共同承認。
- 自動測試與 build 通過。
- 至少完成一次 1000 局模擬觀察。（已完成前置條件，不重跑）
- 至少完成一輪人工試玩紀錄。（流程無明顯問題）
