# Alpha Gate 檢查表

## Gate 結論格式

每次準備進入下一階段時，使用以下三種結論之一：

- GO：可進入下一階段。
- GO WITH RISKS：可進入下一階段，但需追蹤列出的風險。
- NO-GO：暫停推進，先修正阻塞項目。

## GO WITH RISKS 追蹤項

1. Bot 發言已顯示於發言階段，但尚未完成完整人工 UI smoke。
   - 風險：心理壓力已可見，但仍需人工確認不同尺寸下不遮擋操作。
   - 處理：Freeze 前完成桌面與小螢幕 smoke test。

2. 真人測試只記錄高層結論。
   - 風險：缺少逐局時間、結束回合、玩家訪談資料。
   - 處理：若要進入正式調參，再補一輪有量化表格的測試。

3. 工作區有多條未提交變更。
   - 風險：文件、UI、素材、Bot 變更混在同一工作區，後續整合需小心。
   - 處理：進入 freeze 前分批檢查 diff，避免無關變更一起進入。

4. 美術素材體積偏大。
   - 風險：正式分享或部署時載入成本偏高。
   - 處理：Alpha 先不阻塞；部署前再做素材壓縮或分級載入。

## NO-GO 條件

若出現以下任一狀況，不應進入下一階段：

- `npm run test` 失敗。
- `npm run build` 失敗。
- 玩家無法完成一局。
- 文件勝利門檻與程式勝利門檻再次不一致。
- 宿命被誤接回出牌階段或公開型功能牌順序。
- 新增功能牌進入 MVP 但沒有 resolver、Bot 邏輯與測試。
- UI/美術整合造成核心流程無法操作。

## 下一階段建議

若 UI/美術線已準備好，下一步應完成桌面與小螢幕 smoke test，並用本表重新跑一次 Alpha Gate。
